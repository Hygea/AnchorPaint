# Architecture and implementation plan

Updated: 2026-10-24. This is an export-first development preview, not the complete MVP.

## Milestones

1. **A: export round trip.** Build a headless 3MF writer, validate the supplied
   original/modifier meshes, test actual Bambu import/save/reopen, and investigate
   per-layer behavior before claiming compatibility. Headless fixture tools
   support repeatable testing. Source/schema tests do not close this gate.
2. **B: automatic geometry.** Weld an adjacency representation separately from
   the untouched export geometry. Smart Fill follows adjacent dihedral angles.
   Confirm the horizontal root, section just above it, stitch/classify contours
   and holes, associate the chosen feature, then extrude along build Z. Reject
   ambiguity. Validate local support through the full depth, not model-wide Z.
3. **C: interaction.** Arbitrary STL loading with dimensions confirmation,
   selection preview, common depth/overlap/wall settings, multiple anchors,
   remove/undo, and aligned export. No freehand brush or general CAD editing.
4. **D: pilot.** Compare an actual part and ten targets against baseline/manual
   modifiers under the same slicer settings. Physical strength remains a separate
   experiment.

## Components delivered

- `src/core/mesh.ts`: ASCII/binary STL parsing through Three.js, exact-coordinate
  indexing, finite/bounds/degeneracy/manifold/winding/positive-volume checks.
- `src/core/extrude.ts`: a closed-loop extrusion building block, including holes.
  Exact coordinate indexing joins Three's cap/side triangle vertices before
  native 3MF export. No source coordinate is moved and no repair is performed.
- `src/core/selection.ts`: analysis-only tolerance welding, edge adjacency,
  per-neighbour dihedral Smart Fill, upright-side checks and root proposals.
- `src/core/orientation.ts`: explicit axis-aligned build-frame rotation from a
  selected bed face, plus connected coplanar hover regions. No automatic rotation.
- `src/core/anchors.ts`: non-critical Z sections, closed contour stitching,
  nesting/holes, association to selected triangles, constant-section checks,
  primitive scope checks and local support-depth limits.
- `src/export/bambu-3mf.ts`: independent ZIP/XML writer with a single assembly,
  separate normal/modifier mesh resources and per-modifier `wall_loops` metadata.
- `src/export/profile.ts`: settings-only extraction from an explicitly chosen,
  locally saved Bambu project. Its geometry and existing painting are ignored.
- `src/assets/default-bambu-settings.3mf`: 10 KB stock, single-filament settings
  asset. Generated by Bambu from installed system presets; no model or user
  project is bundled. `tools/build-default-profile.ts` regenerates it for review.
- `src/main.ts` and `src/viewer.ts`: local STL file input, raycast selection and
  preview, root confirmation via Add or a separate horizontal base click,
  shared settings, multiple targets, removal/undo and export. The product has one
  selection workflow, an empty start, and one optional sample. Fixture reference
  and known-footprint modes are not bundled in the UI. The viewer never changes
  export vertices or the shared source frame during ordinary selection/viewing.
- `tools/export-fixtures.ts`, `inspect-3mf.ts`, `verify-bambu.ts`: reproducible
  headless export and real-slicer round-trip checks.

There is no account, server API, upload, analytics, general CSG dependency or UI
framework. Vite binds to loopback. All runtime assets are packaged locally.
Polygon-clipping 0.15.7 (MIT) supplies 2D polygon difference/XOR/intersection;
this is not a 3D CSG kernel. See its [primary documentation](https://github.com/mfogel/polygon-clipping).

## Decisions

**One product workflow.** Load → select → export replaces the export-spike
workbench. Depth and wall count are the primary controls; overlap, fill angle
and custom settings are collapsed. Export stays visible independently of sidebar
scrolling. A single optional sample replaces 13 bundled STL assets: runtime
mesh data fell from 579,692 bytes to 38,484 bytes. The full fixture library and
baseline export remain available to tests/developer tools. No dependency was added.

**Surface feedback without geometry changes.** The solid model uses per-face
display colors: blue upright sides and neutral flat tops. Hover Smart Fill is
cached per region/angle and shown in teal; clicking performs the full anchor
validation. This makes selectable sides apparent without falsely marking every
side as supported geometry. Ambiguous base picking previews a connected flat
surface in purple. A purple footprint outline marks the root, and the base height
is shown relative to model bottom rather than offset source Z. Orange volumes
render through the original to show depth; See inside is an optional view mode.

The viewer keeps source, modifiers, selection, hover and root outlines in separate
groups. Hover only replaces its small overlay, not the whole original mesh.
Rendering is event-driven, pointer previews are frame-throttled, and replaced
geometry/materials are disposed. Display triangles preserve original ordering
for raycasting. A drag that returns to its start is still a drag, never a click.
Fit/Top/3D and viewport resize modify only the camera. Browser export checks
compare every original vertex/index after hover, selection and view changes.

**Confirmation at the attempted action.** Hover works as soon as a model is
loaded. An unconfirmed model click opens an accessible native HTML dialog with
the model's dimensions. The pending face and load revision are held until an
explicit confirmation, which checks the existing dimensions control and resumes
that exact selection. Cancellation does not confirm; loading another model
closes the dialog and discards the pending face. Normal canvas shortcuts are
ignored while the modal owns focus. The sidebar checkbox remains optional.

**Depth/overlap sliders and precise input.** Both controls share the same range
synchronization and gesture handling. They are enabled once the current or
added targets provide limits: local base depth for depth, and `topZ - rootZ`
for upward overlap. Each maximum is the minimum across all those targets because
settings are shared. The numeric fields remain independent precise inputs,
including visible rejection for out-of-range values. Slider input updates its
numeric setting and schedules one shared preview update per frame; release
commits immediately. Export/add are disabled during a pending update to avoid
exporting a previous slider value. Slider interaction does not change source
coordinates or the root.

**Keep native dragging separate from controls.** The app has no drag-out action,
so document `dragstart` events are cancelled. Text remains selectable/copyable
outside the slider areas, but dragging an already selected filename or label
cannot begin a browser/host drag. Each slider has a 28 px vertical hit area and
disables text selection and touch scrolling within its gesture. Its native
pointer handling retains control when the pointer moves outside the slider.
The model drop zone accepts only transfers advertising `Files`; unrelated text
drags cannot activate import feedback. Drop, drag end, Escape, window blur and
leaving the workspace clear that feedback. External file drops still load and
validate an STL through the same path as the file chooser.

**Prove exports before selection.** Fixture contours are test inputs, not evidence
of a feature detection algorithm. The workbench says so explicitly. Supplied STL
modifiers and newly extruded known footprints can be compared independently.

**Shared coordinates.** Every mesh resource retains working-frame coordinates with an
identity component transform. A single build translation centers the whole
assembly on the chosen rectangular bed and brings its bottom to Z=0. It rejects
models that exceed the bed with 3 mm clearance or overlap a bed exclusion's
bounding rectangle. The verification tool compares
the reconstructed components in the common object frame. No modifier is placed
or centered independently.

**Conservative automatic features.** Section planes avoid all vertex heights.
Endpoints are stitched using a model-scale tolerance; open/branching contours
fail. Nesting groups holes with their outer contour, and the selected triangle
set identifies the component. Three sections per vertex-height interval check
constant cross-sections. Only rectangular walls and polygonal circular bosses
(optionally one coaxial bore) are accepted. A joined boss/wall is rejected,
even when it has a valid constant section; splitting such features would need
an additional feature-boundary rule beyond the current MVP.

**Explicit printing orientation.** The servo-adapter pilot exposed pins pointing
along source -X. Normal side filling assumed build +Z, so it picked the wrong
surfaces despite the model looking upright after orbiting the camera. Set upright
now lets the user select the flat face to put on the print bed. That face's
outward normal becomes -Z. One proper, integer axis permutation rotates the
entire working mesh, preserving scale, winding, triangle order and every
coordinate exactly apart from axis order/sign. The six signed axes are supported;
sloping/curved faces and arbitrary-angle rotation are rejected. The input disk
file and an in-memory original remain intact. Original orientation restores it.
Changing orientation resets dimensions confirmation, targets, history, pending
clicks and hover caches. The exporter receives this explicitly rotated working
copy and newly derived modifiers in the same frame, then applies its existing
shared bed translation. Default loading still preserves all source coordinates.

**Shaped pin caps.** Filling stays on the upright cylindrical shaft, so a dome or
flare above it does not need to become part of the selected region. A concave
indentation may start below the outer side's top. For round shafts only, the
section check accepts a terminal interior change with an unchanged outer contour
and at most one hole, then limits usable `topZ` to the first changed interval.
It continues checking above that limit: an outer outline change, multiple holes
or a return to the original full section is rejected. The modifier retains the
constant root footprint and never extends into the cap. Tapers, root fillets and
joined/branching footprints remain unsupported. This is not general curved
surface painting or cap reconstruction.

**Local support.** Downward sections test the entire hole-aware footprint against
support material with polygon difference. Support ends at the first unsupported
height interval, not at the mesh-wide minimum. Relevant sloped base triangles
are conservatively rejected using their XY projections so a sloped notch cannot
hide between section samples. This is a conservative check for horizontal and
vertical bases, not a general solid-containment proof. Narrow height intervals,
too many levels, tapering and unresolved geometry produce explicit rejections.

**Target state.** Each in-memory anchor is a plain serializable record with id,
seed, selected triangle region, root/top Z, footprint/holes, local depth limit and
feature kind. Shared depth, overlap and walls live in the app state. Source
coordinates are the shared frame; the exporter applies the common bed transform.
There is no saved AnchorPaint editing project format yet.

**Bundled default and optional override.** Actual GUI testing showed that a
profile-free 3MF can retain modifier geometry but lose wall overrides. The first
prototype required a user-saved settings source. The user clarified that this
extra step was unwanted and requested a bundled default instead. The app now
loads clearly labelled stock P1S 0.4 / PLA / 0.20 mm settings automatically.
Users choose their actual printer/process/filament in Bambu before slicing, or
optionally supply their own settings project under a collapsed section. The
native settings payload and Application marker remain the compatibility mechanism;
Description identifies AnchorPaint as the actual writer. Default generation
reads only installed system presets and lets Bambu produce the full config. It
never reads a user settings directory or edits stock G-code templates.

**Tests without a second test runtime.** Use Node's built-in test runner with
Playwright's assertions, plus Playwright for browser flows. The initial Vitest
3 choice supported the installed Node 23 runtime but had dependency advisories;
current patched Vitest majors excluded that Node release. Node's runner reduced
dependencies and allowed a clean audit. Vite, Three.js, fflate, fast-xml-parser,
TypeScript, tsx and Playwright are pinned in package.json and package-lock.json.
Use maintained Node 22 or 24 LTS for normal development. The implementation was
run here on Node 23.10.0.

## Risks and limits

- Bambu metadata is an application-specific contract. Tests are pinned to the
  installed 2.8.2.61 source tag; other versions require actual verification.
- Keeping source settings can also retain custom printer start/end snippets.
  The app does not edit those snippets or produce toolpaths. Bambu's own warnings
  must be reviewed in the slicer.
- STL has no units. Local files are interpreted in mm, with mandatory dimensions
  confirmation for export. Input size, finite coordinates and scale are checked.
- Three.js uses float32 positions. ASCII STL precision beyond float32 is not
  preserved by this initial loader; use a higher precision parser before claiming
  lossless support for all ASCII inputs. Export round trips preserve loaded data.
- Edge manifoldness and signed volume do not prove absence of self-intersection.
  General mesh repair, taper/fillet handling and automatic ambiguity resolution
  are not implemented.
- The strict loader rejects broken meshes before tolerance-aware analysis.
  Analysis welding never relaxes source manifold validation or repairs a mesh.
  Section welding is deliberately conservative; tiny edges may be rejected.
- A feature's inner bore may continue below its root. An inner-side click cannot
  use its region's minimum Z as the root; it needs horizontal-base confirmation.
- Browser parsing/ZIP work is synchronous with input size limits. Workers may be
  needed for large files after measuring actual selection workloads.
- The folder was not a Git checkout. No existing branch/history was changed.

The current status of every acceptance gate is recorded in TEST_STATUS.md.
